# 发货流程（每单 2 分钟）

服务器：`dl.speakve.com`（182.254.157.23，Ubuntu 22.04，nginx）
下载目录：`/var/www/xiaojing-dl/<32位token>/xiaojing-guard-pro.apk`
下载前缀：`https://dl.speakve.com/xj/`

## 收到一笔付款后

```powershell
# 1. 打一个带买家名字的包（「关于」页会显示「授权给 张三」）
cd E:\fangchenmi
.\tools\make-pro-apk.ps1 -Name "张三"

# 2. 传到服务器，拿到专属链接（默认 7 天有效）
.\tools\publish-apk.ps1 -Apk "dist\pro-张三.apk" -Days 7
```

第 2 步会打印一条链接，形如：

```
https://dl.speakve.com/xj/ea7ac2b96ec6468d9cd7bb633df2648e/xiaojing-guard-pro.apk
```

把这条链接和下面这段发给买家（微信/私信）：

```
小鲸守护付费版：<链接>（7 天内有效）

装的时候直接装，覆盖免费版即可，不要卸载——规则和累计时长都会保留。
装不上随时找我。
```

## 为什么这么设计

| 设计 | 解决什么 |
|---|---|
| 每个买家一个 32 位随机 token 目录 | 链接无法被猜，也不可枚举（`/xj/` 目录列表已禁止） |
| 每人一个包，包内写「授权给 xxx」 | 转发时带着自己名字，心理成本高；泄露可追溯 |
| `.expires` + 每天 04:00 自动清理 | 链接 7 天后失效，泄露的旧链接自然死亡 |
| 同包名同签名 | 覆盖安装免费版，数据不丢，不用重设 |

## 紧急下架某条链接

```powershell
ssh -i C:\Users\Administrator\.ssh\speakveZG.pem ubuntu@182.254.157.23 "sudo rm -rf /var/www/xiaojing-dl/<token>"
```

## 服务器上的东西

| 路径 | 作用 |
|---|---|
| `/var/www/xiaojing-dl/` | 下载根目录（www-data 可读） |
| `/usr/local/bin/xj-cleanup.sh` | 按 `.expires` 清理过期目录 |
| `crontab`：`0 4 * * *` | 每天凌晨跑一次清理 |
| `/etc/nginx/sites-available/dl-speakve` | 新增了 `location ^~ /xj/`；改动前已备份为 `.bak-20261031-221418` |

## 注意

- 这个 nginx 配置同时服务你原有的 `speakve-download` 站点，**只新增了 `/xj/` 一个 location**，其他路径未动。
- 免费版仍然只走 GitHub Releases，服务器只放付费版。
- 服务器上没有做访问统计。想知道有多少人下载，后续可以加 nginx access_log 过滤 `/xj/`。
